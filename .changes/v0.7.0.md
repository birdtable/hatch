## v0.7.0 - 2026-11-25
First public release.

Tested on Linux (amd64), macOS (arm64) and Windows (amd64).

hatch provides, each documented in the [command reference](docs/commands.md):

* `hatch budget` holds a tier to its time, and judges it by wall time or by the CPU time of its tree.
* `hatch tests` runs `go test` and judges the counts by the rule you name; `hatch tests packages` lists the packages of a module.
* `hatch secrets` runs your pinned gitleaks over a history, a range or the staged change.
* `hatch names` checks a hashed list of forbidden names against the tree, the branch and the text you give it.
* `hatch runs` finds which package starts which outside program, and judges that against a rules file.
* `hatch age` refuses a Go module version younger than the window you set.
* `hatch tag` holds a tree to what a release built from it must be, before the tag and after.
* `hatch writes` holds a command to writing nothing under a root.
### Added
* `hatch tag` takes `--prefix <folder>` for a module in a folder of the repository: the tag is `<folder>/<version>`, as Go reads the tag of a module in a folder, and the folder is one or more slash-separated names of lower case, digits, `-`, `.` and `_`, with no `..` and no slash at either end; a prefix that is none is refused before git is asked, and without the flag the tag is `<version>` as before. `--tagged` also holds the tagged commit to be an ancestor of the remote's default branch (read from `refs/remotes/<remote>/HEAD`, or asked with `git ls-remote --symref`), or of the branch `--on <branch>` names: a tag on a side branch is refused, by the branch's name.
* `hatch writes` runs a command and is green only when it wrote nothing under a root: `hatch writes [--root <dir>] [--exclude <name>]... [--max-entries <n>] [--max-bytes <n>] [--timeout <duration>] -- <command> [args]`. It takes a `github.com/birdtable/go-files/treesum` listing of the tree before the command and after it, and names every path added, changed or removed, sorted, one per line, the files git ignores among them. A command that fails keeps its own exit code, with the list printed beside it. What treesum refuses (a device, a FIFO, a socket, a file with a second name, a link out of the tree, a tree over its caps) is a red that names the path, before the command (which is then not run) or after it, and is never skipped. The root defaults to the top of the git checkout, the caps to 200000 entries and 1 GiB, the deadline to 30 minutes. `--exclude <name>` is repeatable and none by default: a name skipped at any depth, passed to treesum as `Caps.Skip`, so an excluded folder is never opened. What is under it is not listed, counted or refused (a hard-linked `node_modules` under pnpm no longer stops the run), a write under it is no write, a write beside it is still named, and a name that matches nothing changes nothing. A blank name or one holding a slash is exit 2. `github.com/birdtable/go-files` v0.16.1 is a direct requirement.
* `hatch secrets --range <base>..<head>` and `hatch secrets --staged`. `--range` passes `--log-opts=<base>..<head>` to gitleaks and is red unless gitleaks's `N commits scanned` equals the commits git's `log --diff-merges=first-parent --numstat <range>` shows adding more than 0 lines: gitleaks v8.30.1 counts only the commits that add text, a merge by its diff against its first parent, so an empty commit and a commit that only deletes, renames or changes the mode of a file or adds a binary or an empty file are in neither count, and the count is not loosened. A range that holds no such commit is red by name, never green. `--staged` passes `--staged`, which has no commit count: it is red on gitleaks's exit, or unless exactly one line of bytes scanned parses, and it is red when that is 0 (nothing staged); it needs no commit. The two are not given together. The whole-history scan is as it was.
### Changed
* `hatch names` reads `--list` and `--exceptions` through go-files' `trust.ReadOwned` (v0.15.0), with a 1 MiB limit: the file is opened without waiting and through no link at the name, checked on the descriptor, and must be a regular file the running account owns (or the system, root on Unix and the system SID on Windows, as a second try) that no other account can write. A link, another account's file, a file another account can write, a file over the limit, a file replaced as it was read, a file on a mount whose owners are not judged and a missing file are each refused with exit 2. The refusal is the flag and a reason taken from the sentinel with `errors.Is`, never the error's text or a path. `names.Run` takes the caller's trusted mounts as a trailing argument. `github.com/birdtable/go-files` v0.16.1 is a direct requirement.
* go.mod requires `github.com/birdtable/go-testkit/taskfile` v0.1.1, for the test of the Taskfile only.
